## Tabletop disposition

The failure scenario identifies the required recovery path: a console independent of Detew and guest networking, followed by recovery to a known VM-110-only baseline and teardown. Proxmox UI access to the running guest console menu is recorded, but offline local authentication, restore and teardown are unverified. The tabletop is planning analysis only and does not pass REC-01. It also does not prove a Detew-specific adapter-detach action; if that action cannot be proven without attaching the adapter, T02 must stop blocked and no attachment is authorized by this plan.

The route/isolation review likewise found the live LAN and WAN addresses share the same household subnet. The written target plan prohibits using them for generated test traffic and requires an external isolation boundary. That boundary has not been inspected or tested. Firewall rules alone are not accepted as proof that packets cannot escape to production.
