## Acceptance criteria

- [ ] False blocks, failures, status misunderstanding and support constraints are linked to exact candidate/dataset/catalog versions and independent evidence.
- [ ] Silent lost enforcement, false applied status, guardrail bypass, secret leakage or unrecoverable accepted-state corruption are release blockers.
- [ ] Each repair has an owned review boundary, acceptance/negative cases and evidence invalidation set; downstream results are rerun when behavior/capacity/data changes.
- [ ] No target/semantic/privacy reduction is made in the issue ledger alone; reviewed scope changes synchronize PRD/product/architecture/milestones/tasks.
- [ ] Negative direction/repeat-use/licensing/attachment/source-maintenance evidence is retained and assessed against PRD stop conditions.
