## Deliverables

- Pinned appliance/kernel/NIC/driver/tool and topology manifest with reproducible provisioning steps.
- IPv4/IPv6 bypass goodput/RTT baseline, packet-path traces, and successful recovery/teardown transcript.

## Acceptance criteria

- [ ] Console login and clean restore/teardown are exercised before adapter attachment; isolation is verified on both IP families.
- [ ] Client-server permitted traffic passes and explicit pf denial stays denied; original-client address/NAT and VLAN stage are captured.
- [ ] Bypass workload results identify packet sizes, flows/new-flow rate, CPU/RAM, tool versions, repetitions and variability; they are baseline observations rather than filtering results.
- [ ] A second provisioning reproduces the topology and required connectivity; absent physical/virtual variants remain unsupported/unmeasured.

## Required tests and validation

- Provision from the documented reset state; generate synthetic HTTP/TLS/UDP flows on IPv4/IPv6 and selected VLAN/NAT paths while capturing client, gateway and server observations.
- Run identical normal workload repetitions in bypass and record goodput/RTT/load/packet counters; verify a deny rule using observed absence of server delivery.
- Disable remote connectivity in the isolated lab, recover over console, and execute teardown; only owned lab changes are restored.
