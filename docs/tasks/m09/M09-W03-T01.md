## Deliverables

## Acceptance criteria

- [ ] Anonymous/read-only/expired-session/cross-site requests and malformed local peers cannot mutate native desired state or attach interfaces; state-changing GET is rejected.
- [ ] Verified Unix peer credentials and filesystem access are required; invalid credentials never default to root and typed helpers accept no arbitrary command/path bridge.
- [ ] Imports/feeds/archives/URLs/front-end strings enforce schemas, bounds, traversal/redirect restrictions, TLS validation and safe rendering.
- [ ] Defaults make no automatic telemetry/crash/correction/browsing-record submission; diagnostic preparation exposes a redacted preview and sends nothing.
- [ ] Retention/deletion/collection-disabled behavior and export scopes match visible promises without secret or payload leakage.

## Required tests and validation

- Packaged native host: run administrator, read-only, unauthenticated, expired session, missing/invalid CSRF and cross-origin mutations including GET; compare native revision and privileged-action audit before/after.
- Native IPC/service-account test: attempt unauthorized socket peers, spoofed credentials, oversized messages, arbitrary paths/commands, malicious imports/archives/redirects and hostile strings; verify refusal and no privilege escalation.
- Synthetic privacy canaries in hostnames, query strings, credentials and payloads: inspect routine logs/diagnostic/export previews and outbound captures; disable collection/delete data and verify advertised behavior and bounded residual audit scope.
