## Deliverables

- Executed package/service lifecycle matrix and migration fixtures.
- Owned-artifact drift/removal rules and recovery instructions.
- Compatible rollback artifact inventory and maintenance-operation behavior.

## Acceptance criteria

- [ ] Supported upgrade/reboot/rollback paths retain accepted intent and only activate compatible dependency versions; failed migration never masquerades as successful applied state.
- [ ] Stop/disable/removal restores only Detew-owned hooks/settings; external changes and unrelated firewall configuration survive.
- [ ] Scope or classifier ABI changes use explicit maintenance; ordinary configuration/data activation does not reattach interfaces.
- [ ] Console/out-of-band recovery is proven for restrictive failure where an adapter cannot maintain a management exemption.
- [ ] Tightly scoped management exemptions are visible and auditable, and cannot allow broad content bypass.

## Required tests and validation

- Pinned native lab: exercise clean install → observe → enforce → compatible upgrade → reboot → rollback → disable → remove; compare native configuration and client/server outcomes at every step.
- Inject power loss/process termination during migration and owned-hook installation/removal, then restart; record recoverable state, drift, and absence of unrelated destructive cleanup.
- Alter one owned hook and one unrelated pf rule outside Detew, simulate interface loss/engine death, and execute console recovery; verify safe drift refusal and documented actual reachability.
