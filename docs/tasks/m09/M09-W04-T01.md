## Deliverables

## Acceptance criteria

- [ ] On identical hardware/configuration below saturation, measured goodput is at least 80% of bypass and p95 added RTT at most 5 ms; saturation, loss and offered-load denominators are disclosed.
- [ ] At least 20,000 active flows and 500 new flows/second fit documented CPU/RAM limits; excess load stays bounded and explicit without silent lost block state.
- [ ] Normal activation and affected-flow reconsideration complete within 5 seconds at reference load; report p50/p95/p99, failures and UI progress, including active and idle tracked flows.
- [ ] Normal local interactive acknowledgment is within 200 ms and common views within 1 second at declared data/list sizes; background activity/updates preserve rendering responsiveness.
- [ ] Packet lookup never waits for SQL/controller/reporting/remote provider, and counters distinguish misses, parser/queue pressure and enforcement failure.
- [ ] All active/candidate bundles, native state, reassembly, queues, control/activity memory, WAL/disk and host headroom are counted together; candidate defaults are proposals until accepted ARCH-G05 evidence.

## Required tests and validation

- Pinned routed IPv4/IPv6 reference appliance, initially four cores/8 GiB/SSD/two supported 1 GbE interfaces without TLS termination: repeat reviewed long/short HTTP/TLS/QUIC/DNS/gaming/unknown/churn workload against bypass and filtering; disclose packet sizes and offered load.
- Drive 20,000 flows/500 new flows per second, then exceed flow/queue/reassembly/admission limits; measure resident/native memory and independent outcomes across configuration/data candidate preparation.
- At reference load apply policy/data/assignment/schedule/override changes while the UI uses five/100/1,000-entry fixtures and activity writes; measure acknowledgment/view and applied/reconsideration timings from independent clocks/instrumentation.
