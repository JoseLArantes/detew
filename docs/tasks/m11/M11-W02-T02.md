## Acceptance criteria

- [ ] Verification instructions work from public artifacts/trust material without unpublished credentials or a hosted account.
- [ ] Tampered/missing/wrong-version artifacts, incompatible classifier ABI/catalog and stale assets are rejected before unsupported enablement.
- [ ] Clean installs are disabled by default, preserve native authentication/pf/routing and expose accurate readiness; supported upgrades/removal preserve unrelated configuration.
- [ ] Rollback/migration/reboot use compatible retained dependencies and tested console recovery, with failed activation visible.
- [ ] Source and notices correspond to every required shipped component and dataset; signature success is not treated as runtime support proof.

## Required tests and validation

- Fresh exact supported appliance with downloaded actual release-candidate artifacts: independently verify signatures/digests then clean install/observe/enforce/reboot/remove using only published procedure.
- Upgrade from each declared supported prior package/schema combination, inject failed migration/activation and perform documented compatible rollback; observe traffic/native ownership/recovery.
- Tamper a copy of package/data/checksum or mismatch catalog/assets and run verification/preflight; confirm meaningful rejection and no silent unsupported protection claim.
