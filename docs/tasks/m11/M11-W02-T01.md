## Deliverables

- Native plugin/runtime/data/static UI artifacts plus published verification/checksum/signature material.
- Pinned build-input/source/classifier/header/feature/catalog/schema manifest and SBOM.

## Acceptance criteria

- [ ] Only the frozen readiness-audited revision and valid admitted software/data rights are packaged; required source is available under the enacted OSI-approved license.
- [ ] Pinned toolchain/locks/base/ports inputs and generic supported amd64 CPU settings are recorded; no target-cpu=native assumption enters release binaries.
- [ ] Signatures/checksums are independently verifiable through published authenticated trust instructions; signing private keys never enter source/logs/ordinary diagnostics.
- [ ] Separate software dependency, classifier catalog and dataset licenses/provenance match actual shipped contents and redistributability.
- [ ] Static UI is locally bundled, Node remains build-only, generated contracts/assets are current, and recovery-compatible artifacts are retained.

## Required tests and validation

- Pinned clean FreeBSD/native builder: build frozen package inputs using established scripts/locks and record exact commands, output digests, SBOM and diagnostic-symbol manifest.
- Independent verification environment: validate signatures/checksums using reviewed public trust material; modify an artifact or manifest and ensure verification fails.
- Inspect shipped files/source/notices/native features and CPU compatibility on supported baseline; compare library/header/catalog ABI and static UI generated-contract identity.
