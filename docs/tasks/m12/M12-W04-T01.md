## Acceptance criteria

- [ ] URL/request matching has documented canonicalization/authority/path/query granularity; runtime/preview/replay use one evaluator with stable reason/version/context identity.
- [ ] Separate requests/authorities on a shared connection receive independent verdict and action outcomes; unrelated allowed requests are preserved where the selected protocol supports it.
- [ ] Request-level allow cannot bypass site guardrails or privileged host firewall denial; missing/unsupported request evidence is explicit.
- [ ] Percent encoding/IDNA/ports/path ambiguity/query handling and malicious authorities have bounded reviewed semantics without browser/PHP-specific divergent policy.
- [ ] Bodies/credentials/sensitive queries are excluded from routine records, and request/connection memory and action/event queues remain bounded.

## Required tests and validation

- Portable shared semantic corpus and selected native TLS path: compare independently specified canonical URL/authority cases across runtime/preview/replay including malformed/ambiguous encoded inputs.
- Managed clients send allowed and blocked cross-authority coalesced/multiplexed requests on one connection; independently observe per-request server delivery and action acknowledgments.
- Drive request floods/oversized authorities, late policy/guardrail changes and event queue loss; verify limits, coherent bundle/context, no cached stale allow and honest incomplete records without sensitive payload.
