## Deliverables

- Dedicated CA generation/import and restricted TLS-service key ownership.
- Exact device/network enrollment/trust verification and tested connection status.
- Expiry/access/ordinary-export exclusions and native authorization review.

## Acceptance criteria

- [ ] TLS remains default off and device/network scope is explicit; installed module/enabled switch alone cannot indicate trust or actual inspection readiness.
- [ ] Reviewed crypto generates/imports the CA, protects its private key with least privilege and confines use to authorized TLS service operations.
- [ ] Enrollment UI exposes exact scope, trust status, certificate expiry and a real test connection; untrusted clients fail accurately without a global bypass.
- [ ] Ordinary configuration/activity/export/diagnostic/logging paths exclude CA private material; key backup requires a distinct explicit secure operation.
- [ ] Native ACL/CSRF/session and typed local IPC protect key/scope changes; browser cannot directly access privileged keys or attach operations.

## Required tests and validation

- Selected native TLS implementation and managed client matrix: generate/import synthetic test CA, enroll one device and leave another unenrolled; verify actual two-sided request inspection only inside scope.
- Unauthorized/read-only/expired-session/invalid-CSRF/local peer attempts to generate/export/use CA or widen scope are rejected; inspect key filesystem/service access permissions.
- Place key/credential canaries in test key material and collect ordinary diagnostics/config/history/logs; inspect that keys are absent and failed/untrusted test-connection states are truthful.
