## Deliverables

- Upstream certificate-validation/error and explicit no-decrypt/sensitive exclusion behavior.
- Strict versus declared metadata-only handling integrated with canonical policy review/reasons.
- Routine URL/query/body/credential minimization rules and negative fixtures.

## Acceptance criteria

- [ ] Invalid/expired/name-mismatched/untrusted upstream certificates cannot become trusted client-side success through the interception CA.
- [ ] Sensitive-service/no-decrypt exclusions are explicit versioned policy scope; strict required inspection blocks failed/excluded inspection unless a separately declared exception permits metadata handling.
- [ ] Pinning/mTLS/handshake error are distinct accurate reasons, never implicit global bypass entries.
- [ ] Site guardrails and canonical exception precedence persist through request/metadata context; TLS inspection does not grant stronger allow authority.
- [ ] Decrypted bodies/credentials/sensitive queries never enter routine logs/activity/diagnostics; declared request metadata is minimized and redacted.

## Required tests and validation

- Selected native TLS/client-server lab: test valid and invalid/expired/name-mismatched/private-root upstream certificates and verify client-visible/result records with independent server observations.

- Inject credentials/body/query canaries and collect routine logs/activity/diagnostic/export views; confirm minimization and absence even across handshake/error paths.
