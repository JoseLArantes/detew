## Deliverables

- Failure injection procedure/matrix for engine/helper death, descriptor close, overload, capture failure and interface reset.
- Observed forwarding/drop/outage/recovery timing, counters, scope and unavailable actions per adapter.

## Acceptance criteria

- [ ] Each injection records actual client/server outcomes and management reachability, not inferred health from PID/socket closure.
- [ ] Bypass/restrictive actions are advertised only where measured; Netmap close is not assumed to guarantee zero interruption or a restrictive action.
- [ ] Overload/parser/resource-limited inspection is distinct from engine death; the matrix records their separate reasons and bounded behavior.
- [ ] No failure test operates on a live production gateway or silently detaches another capture owner.

## Required tests and validation

- In the isolated lab with verified console access, kill engine and helper separately, close descriptors, saturate worker/packet queues and reset the selected interface; probe allowed, previously blocked and management flows over IPv4/IPv6.
- Repeat each claimed failure mode from both idle and active-flow conditions; capture elapsed outage/recovery and actual server delivery.
- Inject an unavailable capture/metadata condition and inspect status; it must not report fully active coverage or silently substitute another failure policy.
