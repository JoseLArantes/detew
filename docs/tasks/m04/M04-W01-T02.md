## Deliverables

- Native mutation boundary covering lock, reread/expected revision, canonical validation, high-water reservation and native save/snapshot.
- Structured stale-edit/conflict and desired-versus-runtime operation state prototype.

## Acceptance criteria

- [ ] The mutation lock spans current native revision reread/check and save; a pre-lock expected-revision check alone is insufficient.
- [ ] Durable high-water reservation occurs before native save and uses checked monotonic counters; failed saves can leave gaps but not reuse successful/reserved revisions.
- [ ] Reserved, saved desired, generated snapshot and applied state remain distinct; the prototype cannot claim actual worker application.
- [ ] Concurrent operation and lock timeout errors preserve drafts and provide stable conflict context without leaking unrelated appliance configuration.

## Required tests and validation

- In the isolated host, submit two synchronized edits with the same expected revision; exactly one saves and the other returns an explicit conflict preserving its local input.
- Pause/inject failure before reservation, after durable reservation and before native save; inspect journal/native state to verify gaps are not reported as saves/applied.
- Restart the prototype after a reserved-but-unsaved revision and perform another edit; monotonic high-water semantics and current native intent remain correct.
